# Attributed project document search

Project document search is an opt-in index of attachment excerpts already selected through the native file chooser. It never opens the original source file, walks the server, reads backup folders, downloads embeddings or invokes a model while indexing/searching. No new package or external service is required. SQLite builds without FTS5 keep existing application features; search reports unavailable instead of loading an extension.

In an offline native project's Workspace, expand **Project document search**, import a document if needed, select it and choose **Add to search**. Import alone does not index it. Search results show the source name, extraction mechanism, excerpt SHA256, chunk number and character range. **Update saved excerpt** explicitly reindexes the stored excerpt; it does not reread a possibly changed original file. **Remove from search** removes the derived search rows and metadata, keeping the imported attachment and source file. Existing direct attachment/per-task references retain their prior behavior. Removal does not claim secure erasure of SQLite free pages, older snapshots or already captured task context.

Only exact project/attachment matches can be indexed. Limits are20documents/project,12,300characters/document and400derived chunks/project. Chunks contain at most900characters with100-character overlap. Queries are1–200characters, normalized to up to12literal Unicode word terms; caller-provided MATCH operators/column selectors/SQL are never executed. Search examines at most40ranked candidates and returns up to10hits. This is lexical matching, not semantic retrieval. Stale/tampered candidates may be omitted; update/remove old entries when references change.

Indexing/reindexing/removal are locked SQLite transactions. A failed insert rolls back the prior complete index. Stored source text/hash/name/mechanism and every returned chunk's offset/body are rechecked before attribution. Stale, missing, renamed, credential-like or altered content is omitted. Admission rejects obvious credential assignments/private-key markers, unsupported control/bidirectional formatting and oversized excerpts; this is not a complete secret-detection system. The source hash identifies the **saved extracted excerpt**, not the original full file or an assertion that the source is correct.

Relevant selected excerpts now feed offline project chats, native/full coding calls and existing approval-bound manual prompts. They remain explicitly untrusted reference data, separate from approved memory facts. Prompt additions are bounded (up to2,200UTF-8bytes; shared with the existing project-context allowance in chat), preserve attribution delimiters, and do not increase the coding prompt limit. Native coding refreshes retrieval per model call, so removing an index prevents future retrieval there. It does not retroactively change existing approved prompts/history. No routing, cloud consent, tool capability or production execution gate changes.

Owner authentication and exact boolean confirmation are required for indexing/removal. Worker credentials cannot use owner routes. Production write admission/main database caps also cover these tables; search creates no separate quota or storage authority. Existing backups include the derived SQLite data. The production200GB free-space reserve and execution-disabled deployment profile remain unchanged.
