# Mission 1B threat model — 2026-11-07

The owner and installation operator are trusted; model output, repository content, filenames, tool descriptions, stored memory and test stdout are untrusted. The API is a trusted control plane. Its compromise exposes its mounted state/credentials; isolating a test process does not make a compromised API harmless. Tailnet membership alone grants no application authority. A stolen valid bearer credential can impersonate its principal until revoked; there is no hardware identity attestation or mTLS.

Production coding remains disabled. The new executor is an operator-only prototype, not a backend execution mode. Local contract tests and a negative macOS check do not prove Linux enforcement. Actual JARVIS kernel/runtime, HTTPS/ACL and storage acceptance are outstanding.

| Attack | Implemented mitigation / evidence | Remaining risk or gate |
| --- | --- | --- |
| Compromised coding agent | API code proposal/patch/command/Git/worktree paths blocked in private profile. Executor sends bounded source via stdin, no host mounts or credentials; fixed reviewed Docker argv and separate operator authority. | Prototype not integrated or run on Linux. API container never receives Docker socket. Kernel/runtime escape remains possible; OS acceptance required before enabling coding. |
| Malicious project repository | Snapshot walks descriptors, rejects symlinks/hardlink aliases/special files/control paths and detects changes during reads. Executor omits Git metadata and rejects secret-named files before reading. No host Git invoked to prepare source. | External editors must be quiescent for a coherent multi-file checkpoint. Legacy direct file tools still use path checks and have TOCTOU residuals; do not run hostile repositories in development mode. |
| Prompt injection / memory poisoning | Model/memory text cannot authorize tools; closed operation vocabulary, digest-bound owner approval, bounded context, evidence-backed memory promotion. | Owner can still approve a harmful proposal. Model/test correctness is not guaranteed. |
| Tool poisoning | No provider-defined tool catalogue executes automatically. Unknown fields, duplicate JSON keys, malformed native output and tool arguments rejected. | Legacy allowlisted interpreters execute arbitrary repository code in development. |
| Malicious filenames / traversal | Canonical relative paths, control/bidirectional path characters rejected in new snapshot protocol; no link/device extraction; no filesystem authority in job messages. Known broad, family and other application roots rejected before new inventory. | This is not a comprehensive DLP classifier or protection from an already compromised host account/administrator. |
| Malicious patch | Exact old-text/hash binding, stale diff refusal, separate immutable approvals, execution ledger. Private deployment patch paths explicitly blocked. | Hashes do not establish patch quality. No automatic host patch application from executor output exists. |
| Command injection | Shell-free argv, reviewed Python unittest prototype entry command; model cannot supply Docker flags, host mounts, env files, daemon URLs or entrypoint. | Repository tests can execute other binaries inside the container. This is OS confinement, not an executable allowlist. |
| Dependency / image compromise | Public official Python OCI manifest/config digests verified and pinned; build context allowlist; no package manager in backend Dockerfile; no job networking/dependency installation. | No layers pulled or image built; signatures/vulnerability scan/build reproducibility not verified. Optional recovery crypto version pinned, but target installation/wheel hashes remain review items. |
| Credential theft | Private owner/worker token files, distinct scopes, native in-memory auth, HttpOnly sessions, no secret logs. Executor receives no auth material. Recovery excludes credential directories and key collection. | Backend or Mac account compromise exposes credentials in its authority. Secrets embedded in ordinary source cannot be detected reliably; operator reviews input snapshot. |
| Unauthorized API / browser | Owner auth, Host/Origin/Sec-Fetch and duplicate header checks, body limits, CSP, same-site cookies, throttled login, bounded clients; real local auth/TLS-rejection tests. | Explicit loopback development may be unauthenticated. Single owner, no per-project role model. Actual private HTTPS and denied-device ACL tests pending. |
| Worker impersonation | Separate worker token cannot act as owner; TLS verification, fixed worker routes, lease validation, installed allowlist. Hot rotation revokes active jobs and rechecks authority after request-body read. | Possession of current worker token permits spoofed model presence/results and prompt access. Restrictive source-device ACL is a deployment gate; no attestation. |
| Replay / ambiguous completion | Mac durable claim commits before Ollama, retained across restart; duplicates never invoke model again. Backend never re-leases expired/interrupted jobs; chunks idempotent only for identical sequence payload. Restores revoke pending/approved approvals and interrupt jobs. | New explicitly approved UUIDs can intentionally repeat work. Journals fail closed at 10,000 claims; no tombstone-discarding reset or archival implementation is approved. |
| SSRF / data exfiltration | Worker only polls explicit verified private HTTPS and fixed loopback Ollama; no URL in job schema, redirect/proxy forwarding or downloads. Job network namespace has no external interfaces/routes by required probe. | Legacy optional external providers remain owner-consent gated; gateway off by default, cloud chat disabled. Network restriction on actual JARVIS executor remains unverified. |
| Resource exhaustion | Four active inference jobs/one worker, two chats, 32 HTTP clients, deadlines and bounded responses/chunks/4096 sequences. Clock rollback cannot extend consumer monotonic timeout. Prototype requests CPU/RAM/PID/tmpfs caps and independent host output/time bounds. | Actual cgroup enforcement pending. Admission uses bounded cached accounting, not a filesystem quota; other host services can consume free space. |
| Storage exhaustion | Production write admission closes near measured allocation/reserve or incomplete inventory; 3 GB margin, 1-second inventory cache, free space every admission. SQLite main DB page cap up to 1 GiB tested; startup refuses unsafe DB aliases. | Page cap excludes journals and other files. Data measurement excludes separately accounted images/source/logs. Preserve 200 GB free/75 GB total with actual overhead review. No hard overall quota. |
| Database corruption | SQLite integrity checks, locked offline checkpoint, authenticated encrypted recovery, new-file-only restore. Running operations interrupted rather than replayed. | A corrupt live DB may need offline recovery; full forensic repair, arbitrary schema recovery and malicious administrator are out of scope. |
| Backup compromise | Fernet authenticated encryption using existing reviewed library; separate private key outside data; manifest/inventory/hash/path verification before restoration. No plaintext staging archive, private-key collection or overwrite. | Encryption key loss prevents restore; key compromise permits forged backups. Timestamp/size visible. Full envelope limited to 64 MiB; larger data needs separately reviewed streaming backup tooling. |
| Malicious model output / fake test proof | Strict schema/digests/terminal validation, completed text matches stream, actual approved test evidence required. Executor stdout remains explicitly untrusted and cannot grant approvals/apply patches. | A malicious repository can make its own tests pass or attempt to spoof stdout. Independent trusted tests and owner review still required. |
| Recovery / stale authority | New root only, DB paths relocated, old approvals revoked, active messages/jobs interrupted, workspaces marked recovery-review, startup refuses incomplete recovery or development execution. | Git worktree/config pointers need isolated repair/review. No automatic restore of credentials, images, models, services or native settings. |
| Publication / supply chain | Local commits only, explicit staging/archive list, protected diagnostic and private deployment files outside Git, retained rollback artifacts. | Native distribution remains ad-hoc signed/not notarized; no automatic update signing infrastructure. Publishing requires approval. |

See [isolation design and acceptance](ISOLATION.md), [recovery contract](RECOVERY.md), [deployment proposal](../DEPLOYMENT.md) and [API contract](API.md). Defaults do not provide cloud fallback or telemetry. No absolute security claim is made.
