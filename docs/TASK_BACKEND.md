# Native task backend contract, version 1

`app/task_backend.py` defines the trusted in-process `TaskBackend` protocol and `NativeTaskBackend`. The existing full-task and command-runner HTTP workflows now call these methods; this is not a second runtime or an unused adapter. Manual digest-approval/round APIs retain their separate exact-review contract. No OpenJarvis runtime dependency or automatic plugin loading is introduced.

| Method | Behavior and authority |
|---|---|
| `plan_task(request, task_id=None)` | Validate authenticated offline coding mode, request shape/budgets, selected project/provider and native filesystem authorization. Capture immutable serialized request values, directory identity, provider descriptor and (for full tasks) Git baseline and selected attachment excerpts. Read-only metadata preparation: no task insertion, model invocation, worktree or project command. Model-based implementation planning occurs later inside the existing bounded runner |
| `execute_task(plan, confirm=True)` | Require a separate exact boolean confirmation and recheck current execution policy, owner mode, provider descriptor, destination identity/path and Git baseline. Delegate to the existing one-at-a-time `project_agent` engine. Full-task scope persists in SQLite on submission; an already-submitted plan cannot be replayed. Old ambiguous work requires explicit resume |
| `inspect_task(task_id)` | Reconstruct existing persisted run/delivery/evidence and bounded contained workspace inventory. Inspection remains available when execution is disabled; owner/offline policy remains required |
| `resume_task(task_id, request)` | Reuse the original persisted full-task scope, source identity/baseline and provider. New full-task scopes also bind exact provider metadata; legacy saved scopes retain their earlier provider-ID binding. Preserve lifetime round/time/cancellation/restart behavior in the existing runner. Command workflow resumes preserve its selected provider-ID/exact command checks |

`TaskPlan` is an immutable metadata snapshot, not a bearer capability, durable queue item or authorization token. Its payload must not be logged. Only trusted application code constructs/passes it; the HTTP API does not accept serialized plans. An unexecuted plan is discarded on restart without work to replay. No automatic inference retry, cloud fallback, network permission, credential, dependency installation or deployment authority is added.

Existing wire shapes remain: `POST /api/full-tasks` returns `{task_id,run}`, `POST /api/tasks/{id}/full-resume` returns the run, command `/autonomous/start` returns the run, and `GET /autonomous` returns current persisted evidence/files. Existing stop/cancel and exact changeset delivery paths remain intact. Missing targets return404, policy refusal403, invalid confirmation/changed scope400. Mutation clients must still never blindly replay a POST.
